# Decision Records

| ID | Decision | Rationale |
|---|---|---|
| DEC-001 | Backend language: **Go** | Cloudflare's container limitation applies to any language, so it is not a reason to switch. Go suits the last-copy concurrency problem, produces a small static binary, and yields a tiny Docker image. |
| DEC-002 | Model non-borrowable copies (reference / on-display) | LIB 001 material: Reference collection is consulted in-room; Recent Accessions "may not be borrowed while on display". A system that lends a dictionary is wrong about HOL. |
| DEC-003 | Reservations / holds **in scope** | LIB 001: on-display books "may be reserved at the Loans desk". The real library does this. |
| DEC-004 | Member categories: undergraduate / postgraduate / staff | LIB 001: serials back-file access differs by category. Privileges are not uniform at HOL. |
| DEC-005 | Loan period and limit **per member category** | undergraduate 2/14d, postgraduate 4/21d, staff 6/28d. |
| DEC-006 | **No self-registration.** Librarian-created accounts + CSV import | Mirrors HOL: users "must present the university identity and library cards and sign the register". Also the more secure design. |
| DEC-007 | External book API seeds bibliographic data only | Africana and OAU Publications are absent from public book APIs. Librarian manual/CSV entry stays authoritative. |
| DEC-008 | Two repositories (backend, frontend). Backend first. | Owned by the student's account. **No AI co-author or contributor trailer on any commit.** |
| DEC-009 | Renewals **deferred to v2** | Not in the project brief. Deferred, not dropped. |
| DEC-010 | Deployment: Render (Docker) + Neon Postgres + Upstash Redis + Cloudflare edge + GitHub Actions | All free with no trial clock. Fly.io and Koyeb no longer offer standing free compute (verified Sept 2026). Cloudflare sits in front as edge, which is how Cloudflare is used in production. |
| DEC-011 | Neon for Postgres rather than Render's free Postgres | Render's free database expires after ~30 days; Neon's does not. Avoids a rebuild the week of the defence. |
| DEC-012 | Notifications: FCM (push) + Resend (email), queued through Redis | Queue decouples request latency from delivery. |
| DEC-013 | Render keep-warm enabled only near the demo window | Continuous pinging to defeat a free tier's idle policy is against the spirit of the plan. Enable for the defence, disable after. |
| DEC-014 | **Time policy: store UTC, display `Africa/Lagos`** | Borrowing, due dates, overdue detection, reminders, audit entries and token expiry are all time. A single canonical zone means they cannot disagree. `TIMESTAMPTZ` everywhere; `DATE` only for date-only values; RFC 3339 on the wire; the server is authoritative for all event timestamps. Full policy: docs/design.md §4A (DES-010). |
| DEC-015 | **Named timezone, not a fixed offset** | `Africa/Lagos` rather than `UTC+1`. A named zone stays correct if the offset ever changes; a hardcoded number does not. |
| DEC-016 | **Embed tzdata in the binary** (`import _ "time/tzdata"`) | The production image is `FROM scratch` and has no `/usr/share/zoneinfo`, so named-zone lookup would fail in production and nowhere else. Costs 0.5 MB. |
| DEC-017 | **Firebase is for FCM push only, not observability** | Crashlytics and Performance Monitoring are client-side products for mobile and web apps; neither has a Go server SDK and neither can observe this API. Backend observability is structured JSON logs carrying method, path, status, duration, request id, actor id and actor role, plus the health endpoint. A log drain or an error tracker with a real Go SDK is a later decision, to be made against a measured need rather than assumed (Article 10). |
| DEC-018 | **Last-copy retention: a title held in two or more circulating copies always keeps one on the shelf** | Requested by the project owner. **Important for the defence: this is our stated policy, not a rule from the LIB 001 material.** That document restricts only the Reference, Recent Accessions, Serials, Africana and Conservation collections; the word "borrow" appears three times in 402 pages and none of them concerns last copies. The threshold matters: a blanket "never lend the last copy" would make every single-copy title permanently unborrowable, stranding most of HOL's Africana and OAU Publications holdings, so a title held in one copy circulates normally. Enforced inside the borrow transaction, after the copy is claimed, so two librarians cannot each believe they are taking the second-to-last copy. |
| DEC-019 | **The activity simulator is called a simulator, not an AI model** | Requested as "a very tiny AI model". It is not one: there is no training data, no learned weights and no inference, `model.json` is 4.7 KB of hand-set probabilities. Naming it AI would invite "what architecture? what did you train it on?", which has no answer and would cast doubt on every other claim in the defence. The pattern's real name is **synthetic monitoring**, which is both accurate and more impressive than a vague AI claim. |
| DEC-020 | **The simulator drives the public API, never the database** | Writing rows directly would populate the catalogue while proving nothing. Going through the API means every pass re-tests authentication, authorisation, validation, the borrowing rules and the concurrency guards. The one exception is its own run log, which is telemetry about the tool rather than library data. |
| DEC-021 | **Everything the simulator creates is flagged `is_synthetic`** | Two reasons: nobody should mistake a simulated borrower for a real student in a report or a conversation with a librarian, and synthetic data must be removable in one statement when the library's real records arrive. Data you cannot separate is data you cannot delete. Simulated members also use a non-deliverable `@simulated.invalid` address so nothing generated can ever email a real person. |
| DEC-022 | **Deploy: Render (Ohio) + Neon + Upstash + Cloudflare** | Ohio rather than Oregon so the container sits beside Neon's `us-east-1`; the earlier plan said Oregon before the database region was known. Render's own Postgres is not used: it expires after 30 days on the free plan, which would mean rebuilding the library's records the week of the defence. |
| DEC-023 | **Neon provisioned through Vercel, not `neonctl`** | The Neon organisation is Vercel-managed, so `neonctl projects create` is refused outright. `vercel integration add neon` provisions the same thing. Recorded because the error message ("organization is managed by Vercel") is not obvious. |
| DEC-024 | **Redis is shared with another application, namespaced** | A free Upstash account allows one database and it was already in use. Every key this system writes is prefixed `holibrary:`, so the two cannot collide. Redis is used for rate limiting only; the notification outbox is entirely in Postgres, so a Redis outage costs limits, not messages. |
| DEC-025 | **Migrations run at startup from an embedded copy** | They previously ran through the Postgres image's `initdb` directory, which exists locally and nowhere else, so a hosted database would have received no schema at all. They now apply under an advisory lock, each in its own transaction, recorded with a checksum. Editing an applied migration is refused rather than reapplied. |
| DEC-026 | **Demonstration data is opt-in and refused in production** | The seeded accounts have passwords published in a public repository. The service refuses to start in production if `SEED_DEMO_DATA` is set, and likewise refuses the published development JWT secret. |
| DEC-027 | **The first administrator is bootstrapped once, never seeded** | A production database therefore starts with no accounts, which is correct and also unusable. `cmd/bootstrap` generates the password rather than accepting one, prints it once, forces a change at first sign-in, and refuses to run twice. Every administrator after the first is created through the API, where the action is attributable and audited. |
| DEC-028 | **Deployment runs through the pipeline, not on push** | Render's auto-deploy builds straight from a commit, before tests have run, which would put an untested version in front of students. It was also silently not working: a service created through the API has no GitHub webhook, so four commits sat undeployed while the dashboard reported auto-deploy enabled. The workflow deploys through the API once every check is green, then smoke tests the running service. |
| DEC-029 | **Proxy headers trusted only behind Cloudflare** | `TRUST_PROXY_HEADERS` is true in production because Render terminates TLS and the origin is not otherwise reachable. It defaults to false everywhere else: `CF-Connecting-IP` is an ordinary header that anyone reaching the origin directly can forge, which would let an attacker dodge the per-IP limit or lock a member out by forging theirs. |
| DEC-030 | **Emails carry a link and a code, in HTML and plain text** | A reset that offers only a 43-character code asks the reader to retype it. The code remains beneath the button because mail clients mangle links and corporate filters rewrite them. Both parts are always sent: the text is what a screen reader and a spam filter read, and a message with no text alternative scores worse with the latter. |
